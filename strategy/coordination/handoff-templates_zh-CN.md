# 📋 NEXUS 交付模板

> 针对 NEXUS 流水线中每种类型的智能体交付所制定的标准化模板。一致的交付能防止上下文丢失 —— 这是导致多智能体协作失败的第一大原因。

---

## 1. 标准交付模板

适用于任何智能体之间的工作移交。

```markdown
# NEXUS 交付文档

### 元数据
| 字段 | 值 |
|-------|-------|
| **发起人** | [智能体名称] ([所属学部]) |
| **接收人** | [智能体名称] ([所属学部]) |
| **当前阶段** | 阶段 [N] — [阶段名称] |
| **任务引用** | [来自 Sprint 优先级规划师 Backlog 的任务 ID] |
| **优先级** | [致命 / 高 / 中 / 低] |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

### 上下文
**项目名称**：[项目名称]
**当前状态**：[目前已完成的工作 —— 请尽量具体]
**相关文件**：
- [文件路径 1] — [包含的内容]
- [文件路径 2] — [包含的内容]
**依赖项**：[此项工作赖以完成的前置条件]
**约束条件**：[技术、时间线或资源约束]

### 交付物请求
**所需内容**：[具体的、可衡量的交付物描述]
**验收标准**：
- [ ] [准则 1 — 可衡量]
- [ ] [准则 2 — 可衡量]
- [ ] [准则 3 — 可衡量]
**参考资料**：[需求规范、设计稿、往期工作的链接]

### 质量期望
**必须通过**：[针对此交付物的具体质量指标]
**所需证据**：[完工证明的具体形式]
**后续交付**：[产出将交付给谁，以及他们需要的格式]
```

## 2. QA 反馈循环 — 通过 (PASS)

当测试证据采集员或其他 QA 智能体批准某项任务时使用。

```markdown
# NEXUS QA 裁定：通过 (PASS) ✅

### 任务信息
| 字段 | 值 |
|-------|-------|
| **任务 ID** | [ID] |
| **任务描述** | [描述] |
| **开发智能体** | [名称] |
| **QA 智能体** | [名称] |
| **尝试次数** | 第 [N] 次（共 3 次） |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

### 裁定结果：通过 (PASS)

### 测试证据
**截图证据**：
- 桌面端 (1920x1080)：[文件名/路径]
- 平板端 (768x1024)：[文件名/路径]
- 移动端 (375x667)：[文件名/路径]

**功能验证**：
- [x] [验收准则 1] — 已验证
- [x] [验收准则 2] — 已验证
- [x] [验收准则 3] — 已验证

**品牌一致性**：已验证 — 颜色、排版、间距均符合设计系统。
**无障碍性**：已验证 — 键盘导航、对比度、语义化 HTML。
**性能表现**：[测得的加载时间] — 在可接受范围内。

### 备注
[任何观察到的细节、对未来改进的小建议或正向反馈]

### 后续行动
→ 智能体编排师：标记任务完成，推进至 Backlog 中的下一项任务。
```

## 3. QA 反馈循环 — 失败 (FAIL)

当测试证据采集员或其他 QA 智能体拒绝某项任务时使用。

```markdown
# NEXUS QA 裁定：失败 (FAIL) ❌

### 任务信息
| 字段 | 值 |
|-------|-------|
| **任务 ID** | [ID] |
| **任务描述** | [描述] |
| **开发智能体** | [名称] |
| **QA 智能体** | [名称] |
| **尝试次数** | 第 [N] 次（共 3 次） |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

### 裁定结果：失败 (FAIL)

### 发现的问题

#### 问题 1：[类别] — [严重程度：致命/高/中/低]
**问题描述**：[问题的确切描述]
**预期结果**：[根据验收标准应当发生什么]
**实际结果**：[实际发生了什么]
**证据**：[截图文件名或测试输出内容]
**修复指令**：[具体的、可操作的解决建议]
**待修改文件**：[确切的文件路径]

#### 问题 2：[类别] — [严重程度]
**问题描述**：[...]
**预期结果**：[...]
**实际结果**：[...]
**证据**：[...]
**修复指令**：[...]
**待修改文件**：[...]

[继续列出所有发现的问题]

### 验收标准状态
- [x] [准则 1] — 已通过
- [ ] [准则 2] — 失败 (参见问题 1)
- [ ] [准则 3] — 失败 (参见问题 2)

### 重试指令
**致开发智能体**：
1. 仅修复上述列出的问题。
2. 请勿引入新功能或做其他改动。
3. 解决所有问题后重新提交 QA。
4. 这是第 [N] 次尝试（最多 3 次）。

**如果第 3 次尝试失败**：该任务将升级至智能体编排师处理。
```

## 4. 升级报告

当某项任务重试超过 3 次时使用。

```markdown
# NEXUS 升级报告 🚨

### 任务信息
| 字段 | 值 |
|-------|-------|
| **任务 ID** | [ID] |
| **任务描述** | [描述] |
| **开发智能体** | [名称] |
| **QA 智能体** | [名称] |
| **重试次数** | 3/3 (已耗尽) |
| **升级至** | [智能体编排师 / 工作室制作人] |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

### 失败历史

#### 第 1 次尝试
- **发现的问题**：[总结]
- **采取的修复**：[开发人员做了什么改动]
- **结果**：失败 — [为什么依然失败]

#### 第 2 次尝试
- **发现的问题**：[总结]
- **采取的修复**：[开发人员做了什么改动]
- **结果**：失败 — [为什么依然失败]

#### 第 3 次尝试
- **发现的问题**：[总结]
- **采取的修复**：[开发人员做了什么改动]
- **结果**：失败 — [为什么依然失败]

### 根因分析
**为什么任务持续失败**：[对底层问题的分析]
**是否为系统性问题**：[这是偶发情况还是某种模式？]
**复杂度评估**：[该任务的范围划定是否合理？]

### 建议解决方案
- [ ] **重新分配**给不同的开发智能体（[建议的智能体]）
- [ ] **拆解**为更小的子任务（[建议的拆解方案]）
- [ ] **修改方案** — 需要变更架构或设计
- [ ] **接受现状**并记录已知的局限性
- [ ] **推迟**至未来的 Sprint

### 影响力评估
**阻塞情况**：[受此影响的其他任务]
**进度影响**：[对整体时间线的影响]
**质量影响**：[若接受现状，会存在哪些质量折衷]

### 需做决策
**决策者**：[智能体编排师 / 工作室制作人]
**截止日期**：[何时需要做出决策以避免进一步延误]
```

```markdown
- [HH:MM] — [事件/行动]

- [HH:MM] — [事件/行动]

### 利益相关者沟通

**下次更新预计时间**：[时间戳]
**沟通渠道**：[发布更新的具体位置]
```

## 使用指南

| 场景 | 推荐使用的模板 |
|-----------|----------------|
| 向另一位智能体分配工作 | 标准交付模板 (#1) |
| QA 批准了一项任务 | QA 通过 (PASS) (#2) |
| QA 拒绝了一项任务 | QA 失败 (FAIL) (#3) |
| 任务重试超过 3 次 | 升级报告 (#4) |
| 在阶段之间切换 | 阶段门禁交付 (#5) |
| Sprint 结束 | Sprint 交付 (#6) |
| 系统事故处理 | 事故交付 (#7) |
